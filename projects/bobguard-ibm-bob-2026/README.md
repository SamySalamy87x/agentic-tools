# BobGuard — Evidence-Gated Modernization with IBM Bob 2.0

**IBM Dev Day: Bob in Action Hackathon · OMROS LAB · 2026**

BobGuard turns risky legacy refactoring into bounded modernization tasks that must pass deterministic behavioral evidence gates before they are considered complete.

## One-line pitch

A Bob-orchestrated modernization workflow that converts legacy refactoring into bounded, regression-gated tasks with reproducible before/after evidence.

## Problem

Legacy modernization is slowed less by writing new code than by uncertainty. Developers must discover hidden business invariants, decompose risky changes, preserve behavior, rerun tests, document evidence, and convince reviewers that the refactor is safe.

## Solution

BobGuard uses IBM Bob 2.0 as the orchestration layer for repository/document understanding, invariant discovery, risk-ranked planning, bounded implementation review, and deterministic validation. The deliverable is not only modified code: it is a reviewable modernization plan plus reproducible evidence.

## What is in this prototype

- `legacy/` — deliberately monolithic Java pricing service.
- `modern/` — modularized target architecture with isolated discount and tax policies.
- `tests/` — deterministic parity and validation harness.
- `run_demo.sh` — one-command compile, test, and evidence generation.
- `evidence/` — JSON, Markdown, and HTML validation artifacts generated by the harness.
- `bob/BOB_RUNBOOK.md` — bounded IBM Bob 2.0 workflow and evidence-capture checklist.

## Run the demo

Requires JDK 17+ and Bash.

```bash
./run_demo.sh
```

Expected result:

```text
PASS parity_cases=8 validation_cases=2
Behavioral parity: PASS
```

The harness also writes `evidence/report.json`, `evidence/report.md`, and `evidence/report.html`.

## Behavioral invariants under test

1. Base subtotal calculation.
2. SILVER 5% tier discount.
3. GOLD 10% tier discount.
4. 3% volume discount at quantity >= 20.
5. SAVE5 and SAVE10 coupon semantics.
6. Region tax semantics for MX, US, and EU.
7. Two-decimal monetary rounding.
8. Non-negative post-discount subtotal.
9. Validation failure for non-positive quantity.
10. Validation failure for unknown coupons.

## IBM Bob 2.0 workflow

1. **Understand** — Bob inspects repository behavior and documents invariants.
2. **Plan** — Bob decomposes modernization into bounded workstreams with explicit acceptance criteria.
3. **Review / execute** — changes are constrained to responsibilities and invariants.
4. **Validate** — `./run_demo.sh` is executed after the bounded change.
5. **Govern** — the final reviewer receives code plus deterministic evidence artifacts.

See [`bob/BOB_RUNBOOK.md`](bob/BOB_RUNBOOK.md) for the exact prompts.

## Why this matters

The differentiator is **governance by evidence**. Bob is not treated as autocomplete. BobGuard makes the agent coordinate understanding, planning, bounded execution/review, regression validation, and reviewer-facing documentation across the modernization lifecycle.
